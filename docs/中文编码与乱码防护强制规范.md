# 中文编码与乱码防护强制规范

最后更新：2026-05-12

本规范用于约束后续所有涉及中文 UI 文案、中文 Markdown 文档、中文注释、中文测试数据的开发工作。当前项目已出现部分中文字符串被错误编码读写后变成乱码的问题，因此本规范为强制执行项。

## 1. 强制原则

- 所有源码、Markdown、JSON、YAML、配置文件中的中文内容必须使用 UTF-8 编码保存。
- 新增或修改中文 UI 文案时，必须确认文件仍为 UTF-8。
- 不允许使用会按系统默认编码读写文件的方式批量重写中文文件。
- 不允许为了“快速替换”而整文件重写包含中文的 Dart、Markdown、JSON 文件。
- 发现乱码时，不得继续基于乱码文本扩写；必须先确认原意，再用 UTF-8 正确文本替换。

## 2. 禁止操作

以下操作默认禁止，除非明确说明编码并已验证输出为 UTF-8：

- 使用 PowerShell `Set-Content`、`Out-File`、重定向 `>` / `>>` 重写包含中文的文件。
- 使用脚本整文件读写中文 Dart / Markdown 文件。
- 使用未声明编码的 Python、Node、PowerShell 脚本批量替换中文。
- 在已经乱码的文件中继续复制乱码字符串作为新 UI 文案。
- 通过终端输出看到乱码后，直接把该乱码内容写回源码。

## 3. 推荐操作

- 小范围修改优先使用 `apply_patch`。
- 修改中文文案时尽量只改目标行，避免整文件重排。
- 大范围修复前先备份或确认当前 diff。
- 如果必须用脚本处理文件，必须显式使用 UTF-8：
  - Python：`open(path, encoding="utf-8")`
  - PowerShell 7+：`Set-Content -Encoding utf8`
  - Windows PowerShell 5.1：避免用于中文文件写入，除非已验证编码结果。
- Flutter/Dart 文件修改后必须运行：
  - `D:\flutter\bin\dart.bat format lib test`
  - `D:\flutter\bin\flutter.bat analyze`
  - `D:\flutter\bin\flutter.bat test`

## 4. 乱码识别

看到以下形态，通常说明中文已经被错误编码破坏：

```text
鏃
閲嶈瘯K绾?
椤圭洰璁板繂
瀵岄€?
```

这类文本不是正常中文，也不是 Flutter 渲染问题。它们通常已经作为错误文本存在于源码或文档中，需要修复源文件。

## 5. 修复流程

遇到乱码时，按以下流程处理：

1. 定位乱码所在文件和行号。
2. 判断原文含义，必要时结合上下文或询问项目负责人。
3. 使用 UTF-8 中文替换乱码文本。
4. 只修改必要行，避免整文件重写。
5. 修改后运行格式化、静态检查、测试。
6. 若是 UI 文案，真机或截图验证显示效果。

## 6. 当前项目特别要求

- `mobile_app/lib/main.dart` 保持薄入口，不因中文修复把业务逻辑塞回主文件。
- `mobile_app/lib/screens/position_detail_screen.dart` 已包含部分历史乱码，后续修改中文时应优先逐步替换为正常中文。
- `docs/项目记忆与交接.md`、`docs/项目开发计划与技术方案整合.md`、`docs/README.md` 当前终端读取时可见乱码，后续如需修复，应作为单独任务处理，不要在普通功能开发中顺手整文件重写。
- 新增文档优先新建 UTF-8 文件，不要继续在已乱码文档中追加大量中文。

## 7. 后续开发检查清单

每次涉及中文内容的提交或交接前，必须检查：

- 是否新增了乱码字符串。
- 是否使用了 PowerShell 默认编码写中文文件。
- 是否对包含中文的文件做了不必要的整文件重写。
- Flutter 是否通过 format / analyze / test。
- 手机端中文 UI 是否显示正常。

本规范优先级高于普通开发便利性。若速度和编码安全冲突，优先保证编码安全。
