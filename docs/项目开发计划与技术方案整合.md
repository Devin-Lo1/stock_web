# 项目开发计划与技术方案整合版

本文档整合 `安卓App一周MVP开发计划.md` 与 `完整技术方案文档.md` 的核心内容，并结合当前项目实际进度更新。后续新 AI 或开发者优先阅读本文档，再按需要查阅原始长文档。

## 1. 项目定位

本项目是一个面向个人持仓监控的智能量化助手 App。第一阶段目标不是自动交易，而是：

- 手动维护持仓。
- 展示实时或准实时行情。
- 计算当日收益、持有收益、涨跌幅。
- 根据阈值生成止盈观察、止损观察、当日异动等信号。
- 后续接入富途 OpenAPI、后端服务、手机推送和 K 线图。

当前开发重点仍是 MVP：

- Flutter Android App 先行。
- 后端 FastAPI 作为行情、持仓、信号、推送的统一服务层。
- 富途 API 由后端接入，不建议 Flutter 端直连 FutuOpenD。

## 3. 推荐技术架构

```text
Flutter Android App
  |
  | REST / WebSocket
  v
FastAPI Backend
  |
  | futu-api / FutuOpenD
  v
FutuOpenD
  |
  v
富途行情与账户能力

Backend
  |
  +-- PostgreSQL / SQLite: 用户、持仓、信号、交易记录
  +-- Redis: 行情缓存、信号队列、推送队列
  +-- Firebase Messaging 或替代推送服务
```

### 移动端

当前选型：

- Flutter
- Material 3
- Dart
- Android MVP 优先

后续可加入：

- `http` 或 `dio`：REST API。
- `web_socket_channel`：实时行情/信号推送。
- `shared_preferences` 或 `sqflite`：本地缓存。
- `riverpod` / `provider` / `bloc`：状态管理。
- 图表库或自定义 `CustomPainter`：K 线图。

### 后端

推荐选型：

- Python 3.11+
- FastAPI
- Uvicorn
- SQLAlchemy / SQLModel
- Pydantic
- PostgreSQL，MVP 可先 SQLite
- Redis，MVP 可延后
- APScheduler / Celery，MVP 可先 APScheduler

### 行情数据

推荐路径：

- 后端运行 FutuOpenD + `futu-api`
- 后端定时或订阅行情
- 后端统一输出 App 所需格式
- Flutter 不直接依赖富途 SDK

原因：

- 富途 Python SDK 更成熟。
- FutuOpenD 长连接和重连逻辑更适合放后端。
- App 不应暴露行情连接细节和敏感配置。
- 后续推送、缓存、信号生成都依赖后端统一数据源。

## 4. MVP 功能范围

### 第一阶段：本地静态 App

已基本完成：

- 首页资产概览。
- 持仓列表。
- 港股/美股切换。
- 添加/编辑/删除持仓。
- 持仓详情页。
- 模拟 K 线预览。
- 本地策略阈值设置。
- 本地信号生成。
- 我的页和显示设置。

下一步应补强：

- 表单校验细节。
- 本地持久化。
- 更完整的空状态和错误状态。
- K 线数据模型。

### 第二阶段：后端模拟 API

目标：

- App 不再只依赖内存数据。
- 后端提供持仓 CRUD。
- 后端提供模拟报价。
- 后端提供策略信号。

建议接口：

```text
GET    /api/positions
POST   /api/positions
PUT    /api/positions/{id}
DELETE /api/positions/{id}

GET    /api/quotes?codes=HK.00700,US.AAPL
GET    /api/signals
POST   /api/settings/strategy
GET    /api/settings/strategy
```

### 第三阶段：Flutter 接后端

目标：

- 新增 API service。
- AppShell 的本地 `_positions` 迁移为远程加载。
- 添加/编辑/删除调用后端。
- 保留本地样例数据作为 fallback。

建议新增：

```text
mobile_app/lib/services/api_client.dart
mobile_app/lib/services/position_api_service.dart
mobile_app/lib/services/settings_api_service.dart
mobile_app/lib/repositories/position_repository.dart
```

### 第四阶段：富途行情接入

目标：

- 后端连接 FutuOpenD。
- 获取实时价格、昨收、涨跌幅。
- 获取 K 线。
- 更新信号计算。

建议后端模块：

```text
backend/app/services/futu_client.py
backend/app/services/quote_service.py
backend/app/services/kline_service.py
backend/app/services/signal_service.py
```

Flutter 侧建议新增模型：

```text
mobile_app/lib/models/quote_snapshot.dart
mobile_app/lib/models/candle.dart
```

### 第五阶段：推送与自动提醒

目标：

- 当触发止盈、止损、异动信号时通知用户。
- 支持消息提醒设置。
- 记录历史信号。

推送方式：

- 优先 Firebase Messaging。
- 如果国内环境不可用，需要准备替代方案，如厂商推送或短信/邮件/企业微信等。

## 8. 开发约束

### 视觉约束

- 持仓列表必须紧凑，适合 20+ 持仓。

## 9. 风险与处理建议

### 富途权限风险

富途行情、K 线、实时订阅可能受账号权限、市场权限、FutuOpenD 状态影响。处理建议：

- 先做后端连接测试。
- 再做单股票报价。
- 再做多股票订阅。
- 最后接 App UI。

### 推送风险

Firebase Messaging 在部分网络环境下可能不稳定。处理建议：

- MVP 阶段先做 App 内信号列表。
- 推送作为第二阶段增强。
- 保留替代推送方案。

### 数据准确性风险

金融数据展示必须避免误导。处理建议：

- 明确行情更新时间。
- 标注模拟数据或延迟数据。
- 不做自动交易。
- 信号只做提醒，不做投资建议。
